# three-layer-spec.md — User→Design→Tech 三层映射规范

> **本文件说明**：这是本 Skill 独有的核心描述框架。  
> 所有场景规范文件（scenes/）和主题文件（themes/）均遵循此三层结构编写。  
> 在做二次开发或扩展新场景/主题时，必须按此结构填写，保持一致性。  
> **加载时机（Tier 3）**：扩展 Skill（新增场景/主题）/ 审查规范质量时按需加载。

---

## 为什么需要三层映射

| 层级 | 解决什么问题 |
|------|------------|
| **User（用户感受）** | LLM 知道应该产生什么样的**印象**，而不只是生成代码 |
| **Design（设计原理）** | LLM 理解**为什么这样做**，能在类似场景泛化 |
| **Tech（技术实现）** | LLM 知道**具体用什么**：CSS 类名 / Token / 数值 |

> 大多数 Skill 只有 Tech 层（`bg-blue-600` 之类的实现指令）。  
> 缺少 User 层 → 模型不知道目标印象，容易偏离  
> 缺少 Design 层 → 模型遇到新场景时无法泛化，只能照抄  
> **三层完整** → 模型能在未见过的场景中做出与规范一致的设计判断

---

## 三层结构写法模板

每个视觉/排版决策都应按以下格式描述：

```markdown
#### [决策名称]

- **[用户感受]**：
  用第一人称或直接感受描述页面给用户的印象，不用专业术语。
  例："整个页面非常亮堂，白白的，带一点蓝色，看起来很理性"

- **[设计原理]**：
  解释为什么这样设计，引用设计语言/原则（Ant Design / Material / 留白理论等）。
  例："遵循 Ant Design 设计语言，强调确定性与自然，用浅色灰蓝区分区块"

- **[技术实现]**：
  给出具体的 CSS 类名、Token 变量、数值范围。
  例：`bg-white` vs `bg-slate-50`；或 `var(--color-bg-page)` = `#F7F9FE`
```

## 示例：Landing Page — 视觉一致性（来自真实规范）

### 视觉一致性

- **[用户感受]**：
  整个页面非常亮堂，白白的，带一点很淡的蓝色背景，看起来很理性、很严谨。

- **[设计原理]**：
  遵循 Ant Design 设计语言，强调"确定性"与"自然"，使用大面积留白与浅色灰蓝背景（Light Grayish Blue）区分区块，而非用颜色装饰。

- **[技术实现]**：
  主背景 `#FFFFFF`，次级区块 `#F7F9FE`（`bg-slate-50` 等价）；  
  区块边界仅用 `1px solid #E5E7EB`，不用分割线颜色块。

---

### 色彩系统

- **[用户感受]**：
  按钮和图标是那种很正的"品牌蓝"，没有花里胡哨的渐变，很克制。

- **[设计原理]**：
  以品牌色作为主行动点和高亮色，背景采用中性灰与极淡的蓝色晕染，保持商务冷静感。颜色的唯一职责是区分语义，不是装饰。

- **[技术实现]**：
  Primary: `var(--color-primary)` = `#1677FF`；  
  Backgrounds: `#FFFFFF` / `#F7F9FE`；  
  Text: `var(--color-text-primary)` = `#1D2129`

## 扩展新场景时的检查清单

新增 `scenes/` 文件时，必须为以下所有条目补充三层描述：

```
必填条目（全场景通用）
[ ] 视觉一致性（整体印象）
[ ] 色彩系统（配色逻辑）
[ ] 字体系统（字阶应用）
[ ] 组件系统（卡片/按钮/表单的质感）
[ ] 间距体系（留白节奏）
[ ] 叙事节奏（模块顺序的逻辑）

选填条目（按场景特性补充）
[ ] 图像/装饰（Landing Page 必填）
[ ] 数据展示（data-report / dashboard 必填）
[ ] 交互模式（tool-app / dashboard 必填）
[ ] 阅读体验（content-doc 必填）
```

## 三层映射在 Agent 执行中的使用方式

当 Agent 需要做一个**规范中未明确覆盖的设计决策**时，按以下顺序推导：

```
1. 找最近的 [用户感受] 描述
   → 这个决策应该给用户什么感受？和最近的描述是否一致？

2. 找最近的 [设计原理]
   → 这个决策背后的原则是什么？泛化到当前情况是什么选择？

3. 找最近的 [技术实现] 作为参考边界
   → 数值范围 / Token 名称给出了决策空间的上下限

4. 做决策，并确保 P0 规则不违反
```

> 示例：用户要求在 Landing Page 中新增一个"合作伙伴地图"模块，规范中未覆盖。  
> → [感受]：应该"整洁、有内容但不乱"  
> → [原理]：高密度栅格，中心定宽，区块化结构  
> → [实现]：`grid-cols-3`，`py-20`，卡片用 `border border-gray-100 shadow-sm`  
> → 合理推断，不违反 P0 ✓
