# core/three-layer-spec.md — 三层映射规范 + 品牌定制推导

> **核心思想**：场景规范描述的是**设计原则和感受目标**，不是固定颜色。  
> 颜色、阴影、圆角等具体数值是"参考实现"——当用户有品牌风格要求时，  
> 这些数值应被替换，但设计原则层（User + Design 两层）保持不变。  
> **加载时机（Tier 3）**：扩展 Skill / 处理品牌定制需求 / 审查规范质量时加载。

---

## 一、为什么需要三层映射

| 层级 | 解决什么问题 | 错误示范 |
|------|------------|---------|
| **User（用户感受）** | Agent 知道目标印象，不只是生成代码 | 只说"用蓝色按钮"，不说为什么 |
| **Design（设计原理）** | Agent 理解设计决策背后的逻辑，能泛化到未见场景 | 只给色值，遇到新场景不知道怎么推 |
| **Tech（技术实现）** | 给出具体可执行的数值/Token，作为参考边界 | 只说"要高级感"，没有可执行指令 |

```
"大多数 AI Skill 只有 Tech 层" ← 这导致 AI 只会照抄，遇到变化就失效

三层完整的效果：
  User 层 → 知道"终态感受"
  Design 层 → 能在新场景做一致的判断
  Tech 层 → 有具体参考，不猜数值
```

---

## 二、三层结构写法模板

```markdown
#### [决策名称]

- **[用户感受]**：
  用"第一人称观察者"视角描述页面给人的印象，不用专业设计术语。
  好例子："整个页面白白的，有一点蓝色，看起来很专业很值得信任"
  坏例子："使用 Ant Design 设计语言"（这是原理层，不是感受）

- **[设计原理]**：
  解释为什么这样设计，引用设计理论/系统（留白/层级/格式塔/对比/重复）。
  好例子："品牌色作为主行动点，背景保持中性，颜色只用于区分语义不装饰"
  坏例子："用 #1677FF" （这是实现层）

- **[技术实现（参考）]**：
  给出具体数值，但标注这是「默认主题 A 的参考实现」，品牌定制时可替换。
  格式：`CSS 类名 / Token 变量 / 具体数值（默认主题 A）`
```

> ⚠️ **关键规则**：Tech 层的数值是"参考实现"而非强制值。  
> 规范的核心在 User + Design 两层，Tech 层跟随品牌/主题动态调整。

## 三、品牌定制：如何用三层框架推导新 Token

当用户提供品牌信息时（颜色 / 风格描述 / 参考图 / 竞品名称），按以下流程推导：

### Step 1 — 提取"感受关键词"

```
用户说 → 提取感受 → 映射设计原则

"科技感、深色"      → 权威/专业/未来 → 高对比 + 深色底 + 细腻字重
"温暖、亲切"        → 柔和/信任/接近 → 暖色调 + 圆角偏大 + 宽行距
"简约、高端"        → 克制/精致/留白 → 大面积留白 + 极少颜色 + 细边框
"专业、大厂"        → 可靠/系统/严谨 → 蓝色系 + 直角偏多 + 密集信息
"活泼、年轻"        → 活力/轻松/互动 → 饱和色 + 大圆角 + 动效明显
"医疗、严肃"        → 干净/信任/精确 → 白绿色系 + 去装饰 + 强信息层级
```

### Step 2 — 从品牌色推导完整 Token 体系

```javascript
/**
 * 给定一个品牌主色，推导完整的 Token 体系
 * 
 * 规则：
 * 1. 主色 = 用户指定色（直接用，不调整）
 * 2. Hover/Active = 主色 HSL 亮度 -10% / -20%
 * 3. Light background = 主色 HSL 饱和度 -60%，亮度 +35%（接近白色）
 * 4. 灰度色 = 主色 HSL 色相保留，完全去饱和（获得"品牌感"的灰）
 * 5. 成功绿 / 危险红 / 警告橙 = 语义色不变（保持识别）
 */

function deriveBrandTokens(brandHex) {
  // 示例推导逻辑（实际执行时用语言描述而非运算）
  return {
    '--color-primary':       brandHex,
    '--color-primary-light': lighten(brandHex, 35),  // 浅色背景
    '--color-primary-dark':  darken(brandHex, 12),   // hover
    '--color-bg-page':       lighten(desaturate(brandHex), 40),  // 页面底色
    '--color-text-primary':  '#1A1A2E',  // 文字色固定（不跟随品牌色）
    // 语义色始终固定
    '--color-positive':  '#18A058',
    '--color-negative':  '#F04848',
  };
}
```

**推导时的口语描述方式**（AI 实际操作时用此格式）：

```
品牌色：#00A870（医疗绿）

推导：
  主色：      #00A870（直接用）
  Hover：     #008A5C（加深 ~12%）
  浅色背景：  #E6F7F0（极浅绿，满版背景可以接受）
  极浅背景：  #F0FBF6（页面底色，几乎白色带绿调）
  卡片底色：  #FFFFFF（始终白色）
  边框：      #C8EAD8（品牌绿调的浅灰绿）
  主文字：    #1A2E24（深绿黑，比纯黑多一点绿调）
  次文字：    #4A6B58（中灰绿）
  辅助文字：  #8AAD9B（浅灰绿）
```

### Step 3 — 将感受关键词映射到设计决策

```
感受关键词        设计决策变化

偏暖色系         → border-radius 适当增大（+2-4px）
                 → 阴影暖化（rgba(xxx, 0.08) 用品牌色而非黑色）
                 → 字体用 PingFang SC 而非 Inter

偏冷/科技感      → border-radius 减小（4-6px）
                 → 分隔线可用虚线代替实线
                 → 优先 tabular-nums，数据精准展示

极简/高端        → 颜色数量减少（只保留 primary + 灰度）
                 → 增大 letter-spacing（-0.01em → 0）
                 → box-shadow 从 sm 减弱到只有 1px border

活泼/年轻        → border-radius 扩大（12-16px）
                 → hover 动画时长加长（200ms → 300ms）
                 → 可以用更高饱和度的图表颜色
```

## 四、场景规范如何与品牌定制配合

每个 `scenes/*.md` 文件的视觉规范，**User 层和 Design 层是品牌无关的原则**，Tech 层是"默认主题 A 的参考实现"：

```markdown
### 视觉一致性

- **[用户感受]**：页面干净整洁，有专业大厂感，颜色克制不花哨

- **[设计原理]**：品牌色只用于行动点和语义高亮，背景中性，
  颜色职责是区分，不是装饰

- **[技术实现（参考 — 主题 A）]**：
  背景 #F7F8FA，卡片 #FFFFFF，品牌蓝 #2563F4
  ↑ 当用户有其他品牌色时，替换 #2563F4 和对应的浅色背景，原则不变
```

**操作规则**：
1. 有明确品牌色 → 替换 `--color-primary` 及其衍生色，其余原则保留
2. 有风格描述（如"更温暖"）→ 用 Step 3 映射表调整 radius/shadow/字体
3. 有参考截图 → 提取参考图的主色相 + 圆角感 + 密度，映射到 Token
4. 无任何指定 → 使用默认主题（场景推荐主题）

## 五、三层推导示例（完整案例）

### 用户需求："给我们公司做一个 Landing Page，我们是医疗 AI 公司，品牌色是 #00B39B（青绿），感觉要专业、干净、有信任感"

**Step 1 — 感受提取**
```
"专业" → 信息清晰，层级严谨，不花哨
"干净" → 大留白，少颜色，白色为主
"信任感" → 避免过于活泼，蓝绿调传递医疗可靠感
```

**Step 2 — Token 推导**
```
--color-primary:       #00B39B（品牌青绿）
--color-primary-dark:  #009682（Hover，-12%亮度）
--color-primary-light: #E5F7F5（选中/Tag背景，极浅青绿）
--color-bg-page:       #F5FBFA（页面底色，极浅带青调）
--color-bg-card:       #FFFFFF
--color-border:        #D0EAE7（品牌调边框）
--color-text-primary:  #1A2E2C（深青黑）
--color-text-body:     #3D5C59
--color-text-secondary:#7A9E9B
```

**Step 3 — 风格调整**
```
"医疗 + 信任" → border-radius 保持 8-12px（不能太方，也不能太圆）
"干净 + 专业" → 去除装饰 blob（或极度降低 opacity ≤ 0.05）
              → box-shadow 只用 shadow-sm，不用 shadow-lg
              → 按钮保持矩形（不用 pill 形）
```

**Step 4 — 叙事结构**（来自 scenes/landing-page.md，原则不变）
```
01. Hero: 一句话价值主张 + CTA（颜色换成 #00B39B）
02. Feature Highlights: 数据背书（字色换成品牌青绿调的深色）
...（结构完全照搬场景规范，只替换颜色 Token）
```

## 六、扩展新场景/主题的检查清单

```
[ ] User 层：每个视觉决策有"第一人称观察者"感受描述（非专业术语）
[ ] Design 层：每个决策有设计原理解释（能让 AI 泛化推断）
[ ] Tech 层：标注"参考实现（主题X）"，不作为强制约束
[ ] 品牌替换点：标出哪些值是品牌色相关（需要随品牌定制替换的）
[ ] 不变点：标出哪些值是场景固定（不随品牌变化：如语义色、字号体系）
```
